## Milestone 1 — DIAGNOSED (fix not yet implemented)

User symptom (2026-10-15 handoff): unpausing produces weird behavior and
numerous error modals. Preserved evidence from the visible run
(`~/.hermes/cache/scratch/orbiter-overnight-20261016/Orbiter_core_metal.log`,
copied from `session-H1uKe5` before reruns) shows exactly one error class:

```
000000.823/.824 (x3): Could not find a module named LuaInline. Tried ./LuaInline.dylib and ./LuaInline/LuaInline.dylib.
000122.847 (x1): same message, during flight right after the unpause window
```

First failing engine boundary (source-backed): the DG vessel's script system —
`DeltaGlider::clbkInitScript` → `ScriptInterface::NewInterpreter` →
`LoadInterpreterLib` → `Orbiter::LoadModule(".", "LuaInline")` fails because
`LuaInline` (and `LuaInterpreter`) are never built or staged in the macOS core
spike (`Src/CMakeLists.txt` only adds `Src/Module` under
`ORBITER_BUILD_LEGACY_WIN32`). The DG subsystems retry interpreter creation
when script callbacks fire during unpaused flight, which matches "numerous
errors after unpause". The on-screen modal rendering itself was not captured as
text; the log entries are the proven error source, modal↔entry mapping is
inference (strong, but stated as such).

New out-of-scope problem discovered: the macOS core build has no native
`LuaInline`/`LuaInterpreter` targets at all, though the `lua` FetchContent
dependency is already populated in the spike build tree and `Script/Demo` +
DG script content assume the module exists. Options for the next session:
(a) add macOS targets for `LuaInterpreter` + `LuaInline` and stage
`LuaInline.dylib` at the content root (engine script path is `.`; the session
staging already symlinks content-root `.dylib` files), or (b) explicitly
disable DG script init in the preview scope — but (b) changes engine behavior
and would still log the failure class. Prefer (a), test-first.

Not yet done for milestone 1: the required red-capable unpaused regression
(bounded unpaused hidden session asserting zero `Could not find a module named
LuaInline` engine-log entries + DG script context state) and the fix itself.
Do not claim the modal problem fixed until that regression exists and passes.
